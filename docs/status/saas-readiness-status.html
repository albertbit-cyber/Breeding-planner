The three gates before you can charge money

These are hard gates, not polish. Each one independently prevents taking a payment; none of them is partially satisfiable.

No payment processing exists

Not started

The billing schema is well ahead of most pre-revenue codebases — priced tiers, a feature catalogue, per-user usage metering and an admin tier editor all work. What has never been built is the part where money moves. Today any signed-in user can switch to any plan for free, so there is no paywall to speak of.

The legal pages still have blanks only you can fill

Blocked Needs your decision

The privacy policy, terms and Impressum are written, live and accurate to what the code does. Twelve values remain unfilled, and they all trace back to one unmade decision: who, legally, is behind Serpentora — sole trader, UG, or GmbH. That is a tax and liability question for a Steuerberater, not a drafting question. It matters more in Germany than elsewhere, because the Impressum is enforced by competitors sending cease-and-desist letters that carry their legal costs, rather than by a regulator.

Started, not finished

Work that exists in the repository but does not yet do the job it was started for. The first item is the one worth acting on.

Multi-tenancy: the frame is up, the building isn't

Partly done

Organization, Membership and OrganizationInvite now exist, the migration is applied, and there are real tenant-isolation tests — the hardest conceptual work is done. But only LabAccount has actually been re-pointed to an organisation. The entire breeder side — animals, pairings, clutches, listings — is still owned directly by individual users. Until that moves, there is nothing to attach a multi-seat plan or a subscription to, which is why this sits underneath the payments gate rather than beside it.

Auth tokens: the safer path exists but is opt-in

Partly done

The backend issues httpOnly cookies with CSRF protection, and the client will prefer them — but only when the API is same-origin. Every other deployment, including the desktop and Android wrappers, still keeps bearer tokens in localStorage. This is the item a security-minded customer asks about first.

checked apiClient.ts — cookie-preferred mode set only when isSameOriginApiBaseUrl(baseUrl)

Known problems

Live or latent defects. None currently stops a user completing a task, but the first is visible in production right now.

A render loop on Settings → My Account

Open

React reports "Maximum update depth exceeded" every time the account tab opens. The page still works, so it is a warning rather than a crash, but it means something is setting state in a loop and it is burning cycles on every visit. It predates this week's work.

observed live in the running app, 2026-08-06 isolated reproduced with this week's changes stashed — 8 occurrences without them vs 6 with, so not introduced by them

Rate limiting never runs outside production

Open

All four limiters skip themselves unless NODE_ENV is production. They are therefore never exercised by a test or in staging, so a bug in the limiter itself would first appear under real traffic — which is the one situation where you need it working.

checked middleware/rateLimiters.ts — skip: productionOnly on 4 limiters

If you do three things next

In this order, because each one is cheaper once the previous is settled.

Decide the legal entity

Yours alone

A short conversation with a Steuerberater unblocks twelve placeholders across three documents and closes an entire launch gate. Nothing technical depends on it, and nobody else can do it for you. It is the cheapest gate to close and it is fully blocked on you.

Finish moving ownership to organisations

Engineering

The frame is built and proven on LabAccount. Every feature shipped before the breeder side follows adds another model to migrate later — this is the only item on the page whose cost rises with delay.

Then wire payments

Engineering

Deliberately third. The schema columns are already shaped for Stripe, but building checkout against per-user billing before organisations own the data means building it twice.
